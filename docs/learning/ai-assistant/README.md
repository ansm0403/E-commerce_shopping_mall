# 관리자 AI 어시스턴트 — 다시 배우는 학습 노트

> **이 폴더는 무엇인가**
> [`docs/roadmap/ex-ai-assistant.md`](../../roadmap/ex-ai-assistant.md)는 **작업 중 시간순으로 쌓인 계획·실측 기록**이다.
> 계획 섹션에 나중 결과가 역주입돼 있고, 트러블슈팅(§8)이 본문 곳곳을 참조해서
> **처음부터 순서대로 읽으면 오히려 헷갈린다.**
>
> 이 폴더는 그 문서를 **"LLM을 처음 접한다"는 가정으로 개념 의존 순서에 맞춰 다시 푼 것**이다.
> 로드맵 문서가 *무엇을 했는지의 기록*이라면, 이 폴더는 *왜 그런지의 설명*이다.

<br>

## 왜 순서를 바꿨나

이 프로젝트에서 실제로 이해에 필요한 의존 관계는 이렇게 생겼다:

```
"LLM API = stateless HTTP"  ← 모든 것의 뿌리
   │
   ├─→ 멀티턴 = 매 요청 전체 재전송 ──→ 입력 토큰 증가 ──→ 프롬프트 캐싱(6장)
   │
   ├─→ Tool Use 루프(2장) ──→ 도구 결과의 PII 마스킹(5장)
   │        └─→ RAG = 비정형 텍스트(3장) ──→ 구매자 리뷰 요약 캐시(4장)
   │
   └─→ 출력이 비결정적 ──→ eval이 필요한 이유(8~9장)
```

**"stateless(무상태)"라는 사실 하나만 제대로 잡으면** 멀티턴·비용·캐싱·eval이 전부 그 파생으로 풀린다.
그래서 1장을 축으로 삼고, 나머지를 거기서 뻗어나가게 배치했다.

## 읽는 법

- 각 장은 **"로드맵 문서의 구절 ↔ 실제 코드"** 를 짝지어 설명한다. 코드 링크는 실제 파일로 연결된다.
- 트러블슈팅(로드맵 §8)은 별도 장으로 몰지 않고 **해당 개념 옆에** 붙였다. 문제를 겪은 맥락 안에서 봐야 "왜 그런 코드가 있는지"가 남는다.
- 각 장 끝에 **셀프 체크**가 있다. 헷갈리면 반드시 틀리는 질문만 골랐으니, 답이 막히면 그 절로 돌아가면 된다.
