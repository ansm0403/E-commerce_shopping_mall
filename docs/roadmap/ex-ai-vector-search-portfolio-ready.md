- **실패 3건은 v2 와 같은 유형이다.** 모두 "내용이나 안내"를 함께 묻는 문항에서 제목만 있는 미답변 문의를 빠뜨리거나(`v3-6`), 표현이 다르다며 낮추거나(`v3-1`), "참고로"로 낮췄다(`v3-7`). 같은 유형 문항의 통과는 v2 답변 완료 9개 중 5개에서 v3 10개 중 7개로 늘었지만 사라지지 않았다. 상태를 지정한 문항과 근거 없음 문항은 v3 에서 모두 통과했다.
- **503 재시도 효과는 이번 실행으로 확인하지 못했다.** v3 실행 중 503 이 한 번도 나지 않아 재시도가 쓰이지 않았다. 실행 실패 8→0 은 그날의 Gemini 상태 차이이며 재시도 개선의 효과로 표현하지 않는다. 재시도 동작은 단위 테스트로만 검증했다.
- v2 와 v3 는 다른 자료이므로 위 표는 같은 문항의 전후 비교가 아니라 같은 구조의 독립 자료 두 개의 결과다.
- **남은 실패 유형의 실사용 영향은 작다고 판단해 여기서 멈춘다(2026-10-14 결정).** 실패는 모두 본문이 빈 "제목만 있는" 미답변 문의에서 났는데, 문의 작성 화면(`frontend/src/lib/validation/inquiry-schema.ts`)이 빈 본문을 막는다. 백엔드 DTO 는 빈 문자열을 받으므로 API 직접 호출·시드로만 생긴다. 본문이 있는 미답변 문의를 "답변 없음"으로 낮추는지는 v2·v3 모두 시험하지 않았다.
- 구조 개선 후보(출처별 관련 여부를 먼저 판정하고 서버가 근거 목록을 만드는 2단계 답변, 답변 모델 교체)는 비용 대비 실익이 작아 보류했다. 로드맵의 Claude 전환 때 새 독립 v4 로 함께 재측정한다.

## 사람이 검토하는 방법

리뷰 검토 화면은 다음 파일을 탐색기에서 더블클릭해 브라우저로 연다.

[리뷰 30문항 검토 화면](../../backend/eval/results/search-answer-review-search-assistant-final-2026-10-13T11-07-46-261Z.html)

문의 v1의 부분 실행·개선 참고용 화면도 제공한다. 실행되지 않은 5문항은 답변이 없으므로 이 화면으로 최종 30문항 평가를 완료할 수 없다.

[문의 v1 부분 검토 화면](../../backend/eval/results/search-answer-review-search-inquiry-answer-audited-search-inquiry-answer-final-2026-10-13T22-15-51-092Z.html)

1. 검토자 이름을 입력하고 각 문항의 질문·정답 조건·실제 도구 인자·반환 원문·답변을 비교한다. 에이전트 참고 의견과 모델 보조 판정은 최종 판정이 아니다.
2. 상품·기간·상태, 실제 근거와 인용, 긍정/부정 및 제목/본문/답변 구분, 추가 주장, 근거 없음/장애 구분의 다섯 기준을 판정한다. 모두 충족하면 해당 문항의 원문 대조 완료 버튼을 누른다. 실패는 해당 기준을 실패로 선택하고 이유를 적는다.
3. 판정 JSON을 저장해 `backend/eval/results`에 복사한다. 중간 저장 파일은 같은 화면에서 다시 열어 이어서 검토할 수 있다.
4. 검증 CLI로 원문 보고서 SHA256·문항 ID·검토자·판정 시각·미검토·실행 실패를 확인한다. 전체 실행과 전체 사람 판정이 갖춰져야 확정 성공률을 출력한다. 부분 실행이나 미검토 상태에서는 성공률이 null이다.

리뷰 13번(`final-v2-5-meaning`)은 높은 별점의 동일한 불만을 참고로 처리한 해석, 25번(`final-v2-9-meaning`)은 원문에 없는 작성 의도 추가를 특히 대조한다. 기존 judge의 오류와 판단 모순도 표시했다. 이 검토는 **기존 측정 당시 코드의 답변**에 대한 기록이며 이후 보완된 프롬프트의 성공률을 대신하지 않는다.

```powershell
yarn nx run '@shopping-mall/backend:search:answer:review' --report=eval/results/search-assistant-final-2026-10-13T11-07-46-261Z.json --review=eval/results/human-review-search-assistant-final-2026-10-13T11-07-46-261Z.json
```

## 문의 평가의 재개

Gemini는 분당 요청·입력 토큰·일일 요청 등 프로젝트의 한도를 검사한다. 429만으로 어떤 한도인지 확정할 수 없으므로 [AI Studio의 사용 한도](https://aistudio.google.com/rate-limit?timeRange=last-28-days)와 [공식 설명](https://ai.google.dev/gemini-api/docs/rate-limits)을 확인한다. API 키를 바꾸어도 같은 프로젝트의 한도를 별도로 얻는 것은 아니다. 결제 설정이나 사용 모델은 변경하지 않았다.

v2의 dry-run은 DB·API 요청 없이 계획과 자료 SHA256을 확인한다. `--live`는 전용 평가 DB와 실제 Gemini를 사용한다. 세 번의 연속 터미널 오류에서 중단하고, `--only` 실행은 별도 부분 결과로 보존한다. 한도 회복 후 독립 v2를 실행하며 이전에 실패한 v1 전체를 반복해 새 최종 결과로 표현하지 않는다.

```powershell
yarn nx run '@shopping-mall/backend:search:inquiry:answer:eval'
yarn nx run '@shopping-mall/backend:search:inquiry:answer:eval' --live
yarn nx run '@shopping-mall/backend:search:worker:demo'
yarn nx run '@shopping-mall/backend:search:worker:demo' --live
```

## 재현과 검증

백엔드 전체 단위 **840/840, 56개 스위트**, 관리자 HTTP/SSE **15/15**를 통과했다. 사람 판정 집계의 미검토·원문 불일치·중복 ID·부분 실행·실행 실패 및 복구한 도구 인자 오류를 단위 검증에 포함한다. 백엔드·평가 타입 검사, lint와 개발 빌드도 통과했으며, 검토 HTML의 초기 미검토 상태·문항 이동·단일 문항 판정·JSON 저장·실행 실패의 통과 차단을 jsdom으로 확인했다. 기존 Nx lockfile fallback·Node 경고는 유지된다. HTML QA의 가상 검토 결과는 실제 평가 파일에 저장하지 않는다.
