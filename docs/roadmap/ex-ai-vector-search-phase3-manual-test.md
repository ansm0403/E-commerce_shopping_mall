아래는 검증에 사용한 재현 절차와 중간 이력이다. 각 독립 조건과 수정·삭제 후 검색은 관리자 화면의 **새 대화**에서 실행한다. 구매자 화면에서 리뷰를 수정·삭제하고 관리자 화면에서 검색한다. 체험 계정의 수정·삭제 제한이 적용되면 실제 리뷰를 작성한 일반 계정을 사용한다.

## 1. 별점과 기간 필터

2026-10-14 사용자 중간 결과: 2점 이하 질문과 곰팡이 질문은 생성 오류로 미완료, 기간 질문은 원본 없음으로 정상 응답했다. 합성 재현에서 Gemini 첫 요청의 503을 확인하고 1회 재시도·안전한 오류 분류를 보완했다. [생성 오류 진단 기록](./ex-ai-vector-search-stream-errors.md)을 참고하고, 백엔드 재시작 후 실패한 두 질문을 기존 리뷰로 다시 확인한다.

02:37~02:40 추가 로그에서도 503 뒤 약 31초 대기 후 실패했다. SDK의 기존 30초 시간 초과를 연결 오류로 분류하던 처리를 수정하고 요청 대기 기본값 60초·턴 누적 SDK 대기 180초, SSE 주석 heartbeat, 오류 뒤 진행 알림 정리를 적용했다. 추가 합성 실모델 요청은 60초 시간 초과로 끝났으므로 두 질문은 계속 **미완료**다. 백엔드 재시작·프론트 새로고침 후 새 대화를 사용한다. 오류가 계속되면 리뷰를 바꾸거나 재색인하지 말고 `code`, `httpStatus`, `timeoutScope`, `timeoutMs`, `sdkWaitMs`를 기록한다.

[사용자 결과 원본](../../backend/eval/results/search-manual-stream-recovery-2026-10-14.json)은 앞선 실패 기록과 별도로 보존했다.

## 종료와 다음 검토

최신 사용자 제공 결과에서 기간은 “제한 없음”으로 명시됐고, 색인 대기 시 `indexing`을 안내한 뒤 “다시 시도해줘”라는 후속 질문에 #1874의 수정한 긍정 원문을 인용했다. 삭제 후에는 원본 없음으로 답해 삭제한 리뷰를 인용하지 않았다. 앞선 임의 최근 1개월 답변은 이력으로 보존한다. 명시적으로 기간 제한을 배제한 질문의 통과를 모든 자연어 표현의 범위 정확성으로 확대하지 않는다.

테스트가 끝나면 `backend/.env`의 `AI_SEARCH_REVIEWS_ENABLED=false`로 복원하고 백엔드를 재시작한다. 이번 로컬 검증에서는 `AI_SEARCH_WORKER_ENABLED=false`를 유지하고 전체 기존 리뷰의 backfill을 실행하지 않는다.

[최종 30문항 사람 검토](../../backend/eval/results/search-human-review-2026-10-13T11-17-44-591Z.md)는 별도 남아 있다. 이미 생성된 질문·조건·도구 결과·답변을 대조하는 오프라인 검토이며 추가 모델 호출은 필요 없다. 각 사례의 미검토를 통과/실패로 바꾸고 이유를 적는다.

다음 구현은 설계 4단계의 공개 문의 의미 검색이다. 제목·본문·답변 문서 구성, 생성/수정/답변 변경의 버전·작업 기록, 공개/비밀 전환·삭제의 제외, 일반·체험 저장 경로와 `summarize_inquiries(query)` 연결을 검증한다. 공개 활성화는 별도 조건을 충족한 뒤 진행한다.
