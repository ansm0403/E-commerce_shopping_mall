# 자동 검색 반영과 포트폴리오 영상 시연

2026-10-14 KST. 격리된 실제 자동 워커 검증은 9/9 완료했다. 아래는 사용자가 실제 계정 화면에서 자동 반영을 확인하고 2~3분 영상으로 기록하는 절차이며, 영상 자체는 아직 촬영하지 않았다.

## 실행 준비

`backend/.env`에 아래 세 값을 설정하고 실행 중인 백엔드를 `Ctrl+C`로 중지한 뒤 다시 실행한다. 현재 서버가 떠 있는 터미널을 사용해 포트가 중복 점유되지 않게 한다.

```dotenv
AI_SEARCH_INQUIRY_INDEX_ENABLED=true
AI_SEARCH_INQUIRIES_ENABLED=true
AI_SEARCH_WORKER_ENABLED=true
```

```powershell
yarn nx run '@shopping-mall/backend:serve'
```

기존 프론트를 열고 구매자·해당 상품 셀러·관리자 세션을 구분한다. 삭제 시연은 일반 구매자 계정을 사용하며 셀러 답변을 받은 문의는 구매자가 삭제할 수 없다. 리뷰 작업 생성 플래그도 켜져 있으면 같은 워커가 리뷰 작업을 함께 처리한다.

## 자동 반영 확인

기존 상품 253을 해당 셀러로 답변할 수 있으면 사용한다. 다른 상품이면 아래 253을 실제 상품 ID로 바꾼다. 기존 답변 완료 문의 #148은 그대로 두고 **별도 문의 D**를 작성한다.

- 제목: `자동색인 시연: 빵이 너무 단단합니다`
- 본문: `빵이 딱딱해서 씹기 어렵습니다. 부드럽게 먹는 방법을 알려주세요. 테스트 연락처 fixture@example.com, 010-1234-5678입니다.`
- 공개 문의로 저장하고 새 문의 ID `I_D`를 기록한다.

`search:inquiry:work`는 실행하지 않는다. 서버의 워커 로그에서 `inquiryId=I_D`, `version=1`, `status=done`을 기다린다. 다른 준비된 문의가 있는 범위에서는 일부 자료가 먼저 반환될 수 있으므로 해당 ID를 비교한다. 워커가 빠르게 끝났다면 색인 대기 안내를 반드시 재현할 필요는 없다.

> 상품 253의 전체 기간 공개 문의에서 빵이 단단해서 씹기 어렵다는 내용을 의미 검색으로 찾아줘. 문의 ID와 원문을 인용해줘. 기간 제한을 추가하지 말아줘.

문의 D의 ID·실제 인용과 마스킹을 확인한다. 셀러 화면에서 다음 답변을 저장한다.

> 전자레인지에 10초 정도 데우면 부드러워집니다. 테스트 연락처 fixture-answer@example.com입니다.

워커의 `inquiryId=I_D`, `version=2`, `status=done` 이후 새 대화에서 확인한다.

> 상품 253의 전체 기간 답변 완료된 공개 문의에서 빵을 부드럽게 먹는 방법을 의미 검색으로 찾아줘. 문의 ID와 판매자 답변 원문을 인용해줘.

기존 #148이 함께 반환돼도 새 D의 답변 반영 여부를 대조한다. 준비된 일부 자료를 전체 자료처럼 설명하면 안 된다. 임베딩 처리나 앞선 대기 작업으로 반영 시간이 늘 수 있으며 503·429는 근거 없음으로 판정하지 않는다.

삭제 확인은 별도 미답변 문의 E로 진행한다. 제목과 본문에 `자동삭제 시연 문구`를 넣고 자동 색인이 완료된 뒤 검색에서 E의 ID를 확인한다. 구매자 화면에서 삭제한 직후, 새 대화에서 그 문구를 검색해 E가 제외되는지 확인한다. 삭제 후 수동 워커 명령은 필요 없다.

## 영상 구성

| 구간 | 보여줄 내용 | 설명할 핵심 |
|---|---|---|
| 0:00~0:20 | 기존 질문 표현과 다른 원문 | 같은 뜻의 표현을 검색하는 문제 |
| 0:20~0:55 | 공개 문의 작성 → 워커 로그 → 관리자 검색 | 원본 저장과 자동 색인의 연결, 실제 문의 ID |
| 0:55~1:25 | 판매자 답변 → 새 버전 완료 → 답변 인용 | 최신 답변과 연락처 마스킹 |
| 1:25~1:50 | 미답변 E 삭제 → 검색 제외 | 이전 원문을 다시 인용하지 않는 처리 |
| 1:50~2:20 | 평가 표와 구조 설명 | 합성 자료 규모·검색 지표·아직 없는 최종 답변 성공률 |

대기 구간을 줄여 편집한다면 경과 시간을 표시한다. `.env`의 API 키나 원문 연락처는 촬영하지 않고 공개 화면의 마스킹 결과와 안전한 워커 로그만 보여준다. 시연 중 API 한도가 남아 있는지 먼저 확인한다.

화면 확인 후에는 실제 테스트한 문의 ID, 각 버전 완료 로그, 수정·삭제 반영 결과와 촬영 날짜를 이 문서에 추가한다. 격리 워커 테스트와 실제 화면 확인을 서로 대체해 완료로 기록하지 않는다.
