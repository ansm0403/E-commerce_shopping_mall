## 디자인 — 사용자 피드백을 반영한 공간 재구성

첫 구현의 흰색·코발트·직선 매거진이 기존 쇼핑몰과 배치 차이가 작다는 사용자 피드백을 반영했다. 최종 방향은 ‘일상과 상상 사이의 오브제 갤러리’다. 초기 매거진 레이어 위에 `mystic.css`로 구매자 공간을 재구성한다.

- 입구: 밤색 공간에 큰 한국어 문장과 얇은 궤도 장식을 배치한다. 왼쪽 소개와 오른쪽 아치형 메인 슬라이드가 서로 다른 축을 이루며 보조 배너 2개가 아래에서 겹쳐 떠 있다. 균일한 가로 배너 지면을 없앴다.
- 상품 방: 장면 소개 → 왼쪽 좁은 안내 영역 + 오른쪽 3열 오브제 배치다. 상품의 높이와 원형/아치형 사진 면을 달리하고 이름·가격은 사진 아래에 둔다. 모바일은 높이가 엇갈리는 2열이며 DOM의 평점순은 그대로 유지한다.
- 여섯 세계: 별도의 연보라 공간 안에 API 카테고리별 이미지와 실제 카테고리 링크를 배치한다. 데스크톱 6개, 태블릿 3개, 모바일 2개를 높이가 엇갈리는 타원형 진열로 만든다. 배경 장식은 CSS만 사용하며 새 자산이나 라이브러리는 없다.
- 중간 장면: 어두운 타원형 그라데이션 패널과 큰 문장으로 상품 격자의 반복을 끊는다. 신상품도 서로 다른 높이로 배치한다.
- 기획전 목록: 아치형 이미지가 좌우 다른 높이로 이어지는 갤러리다. 상세 소개·상품 목록·상품 상세·인증·장바구니·주문서·마이페이지는 연한 보라/흰색의 읽기 쉬운 면을 유지한다. 푸터는 어두운 공간으로 닫는다.
- 콘솔 레이아웃과 전역 색상 토큰, 인증·주문·결제·찜·문의 처리 코드는 유지했다. 배너의 GSAP 동작과 이미지 비율 보존도 그대로다.

## 유지한 기능과 보완

배너 순서 `main_banner3 → main_banner2 → main_banner1`, 5개 기획전 링크, GSAP 자동 슬라이드·hover·포커스 정지·수동 조작·키보드·움직임 줄이기를 유지한다. 인기 상품의 `rating DESC`와 `filter[rating][gt]=0`, 전체 보기의 `rated=true`를 유지한다. 기획전의 API 트리와 slug 기반 조건, 정렬, 12개씩 더 보기, 재시도·빈 상태·404도 유지한다.

상품 사진은 기존 ProductPhoto와 비율 보존을 재사용한다. SSR 이미지 실패가 hydration 전에 완료되어 오류 이벤트를 놓치는 경우에도 대체 사진으로 전환하도록 ProductPhoto에 초기 이미지 상태 확인을 추가했다. 숫자 문자열 가격·평점, 누락 specs·reviewCount·wishCount에 대한 기존 폴백은 유지한다.

`verify-banner.mjs`의 크기 검사는 새 비율에 맞췄으며 기능 검사는 유지했다. 키보드 포커스 정지·보조 이미지 디코딩 검사도 추가했다. `verify-events.mjs`에는 API 503 → 재시도 복구와 빈 상태 검사를 추가했다. `verify-refresh.mjs`의 리뷰 버튼 선택은 실제 집계가 있는 `리뷰 (4)`도 인식하고, 캡처 전에 모든 사진 또는 대체 사진이 로드되었는지 검사한다.

## 실행과 검증

로컬에서 실행 중이던 실제 API `http://127.0.0.1:4000/v1`를 재사용했다. DB 전수 조사·SQL 수정·마이그레이션은 하지 않았다. 이전 3100 포트 프리뷰를 종료하고 최종 브랜치 소스로 운영 빌드를 다시 만든 뒤 `preview-local.mjs`의 `next start`로 실행한다.

```powershell
$env:PATH="$pwd\node_modules\.bin;$env:PATH"
$env:NX_DAEMON='false'
$env:API_PROXY_TARGET='http://127.0.0.1:4000/v1'
$env:NEXT_PUBLIC_API_URL='/api'
node node_modules/nx/bin/nx.js build frontend --skip-nx-cache
node node_modules/nx/bin/nx.js lint frontend --skip-nx-cache
node scripts/design/preview-local.mjs
# 다른 터미널
node scripts/design/verify-banner.mjs
$env:DESIGN_RESULTS_DIR='tmp/refresh-design-mystic-events'
node scripts/design/verify-events.mjs
node scripts/design/verify-refresh.mjs --base http://127.0.0.1:3100 --out tmp/refresh-design-mystic
```

## main 반영 요청과 배포 범위 (2026-10-10)

사용자가 최종 디자인 확인 후 `main` 반영과 원격 push를 요청했다. 초기 구현 단계의 main 변경 금지·push 금지 조건은 이 후속 요청으로 대체한다. 원격 최신 `main`은 `b0f9038`이며, 반영 범위는 기존 디자인 커밋 `1bc4526`과 이번 디자인 변경이다. 기존 `feat/refresh-design`과 지정된 stash는 계속 보존하고 `.yarn/install-state.gz`, 환경 파일, 생성된 프리뷰/검증 결과는 새 커밋에서 제외한다.

이번 디자인 변경은 프론트·검증 스크립트·기록에 한정한다. 다만 main에 아직 없는 기존 `1bc4526`에는 `ProductResponseDto`의 `specs`, `reviewCount`, `wishCount` 노출 및 회귀 테스트가 포함되어 있다. 누락 필드에 대한 프론트 폴백이 있으므로 기존 운영 API로도 웹 디자인은 동작한다. 이 필드를 운영 상품 응답에 새로 노출하려면 백엔드 배포가 별도로 필요하다. DB 스키마/마이그레이션 변경은 없으며 이번 요청에서는 EC2 백엔드 배포를 수행하지 않는다. 저장소 README에 기록된 배포 방식은 main push에 따른 Vercel 자동 배포다.

main 반영 전 CI 영향 확인을 위해 백엔드 전체 lint도 재실행했다. 기존 기록과 동일한 오류 67개·경고 115개로 실패했고, 다수는 `@nestjs/typeorm`을 같은 프로젝트 내부 import로 오판하는 Nx 모듈 경계 검사다. 이번 변경에서 백엔드 lint 설정이나 무관한 코드를 수정하지 않았다. 이는 프론트 빌드/TypeScript/lint 및 화면 검증 통과와 구분하며, GitHub CI의 실제 결과는 push 이후 별도로 확인해야 한다.

디자인 커밋 `48f12a6`을 만들고 main에 fast-forward 반영한 뒤 origin/main으로 push했다. 기존 디자인 브랜치와 stash의 SHA, 로컬 Yarn 상태 파일의 SHA-256이 작업 전후 동일함을 확인했다. GitHub 상태 API에서 쇼핑몰 Vercel 배포 완료를 확인했고, 운영 앱 프로젝트는 Ignored Build Step으로 건너뛰었다.

첫 GitHub CI는 lint를 통과했지만 테스트 단계에서 실패했다. 백엔드 36개 suite·437개 테스트는 모두 통과했고, 프론트는 18개 suite 중 홈 렌더링 테스트 1개가 실패했다. 원인은 `frontend/specs/index.spec.tsx`의 jsdom 환경에 `window.matchMedia`가 없어 새 배너의 움직임 줄이기 설정을 읽을 수 없는 것이었다. 같은 실패를 로컬 프론트 전체 테스트에서 재현했다. 기존 홈 테스트에 MediaQueryList 형태의 API 모의를 제공하고 배너 영역·다음 버튼·인기 상품 제목의 렌더링 확인을 추가했다. 실제 배너 구현이나 브라우저의 움직임 줄이기 동작은 수정하지 않는다. 위 로컬 백엔드 lint 실패와 원격 CI 실패 원인은 서로 다르다.

보완 후 Nx 캐시를 건너뛴 프론트 전체 테스트는 18개 suite·193개 테스트 모두 통과했다. 프론트 전체 lint도 오류 0개·기존 경고 29개로 통과했다. 후속 수정은 홈 테스트와 이 기록에만 한정하며 운영 UI/백엔드 코드에 추가 변경은 없다.

## 한계

현재 로컬 API의 일부 외부 상품 사진은 실패하거나 응답이 오래 대기한다. 공개 화면 검증은 외부 사진을 실제 요청하되 8초 제한 후 요청을 중단해 기존 오류 대체 사진이 로드되는지 검사한다. 따라서 모든 외부 원본 사진의 정상 제공을 보증하는 검증은 아니다. 비활성 배너는 지연 로드를 유지하며 별도 배너 검사에서 확인한다. 기존 자산인 배너 안의 할인율·행사 기간 문구는 실제 공통 혜택으로 적용하지 않는다. 기획전 안내에서 실제 상품 가격·할인율·재고가 기준임을 유지한다.

장바구니·주문서·계정은 브라우저 내부 픽스처 검증이다. 운영 로그인·주문 생성·결제·계정 변경·AI 요약 생성은 검증하지 않았다. 운영 API를 타깃으로 다시 빌드한 검증이나 원격 push·merge·배포도 수행하지 않았다.
