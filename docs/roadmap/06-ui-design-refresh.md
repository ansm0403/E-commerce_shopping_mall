# 구매자 UI 디자인 개편

## 방향과 범위

흑백·Pretendard 기반의 기존 디자인을 이어서, 따뜻한 흰색 배경과 차분한 녹색 면, 큰 상품 사진과 여백으로 라이프스타일 편집숍에 가까운 화면을 구성했다.

- 홈: 브랜드 소개 + 이미지 배너 → 카테고리 컬렉션 → 인기 상품 → 취향 탐색 안내 → 카테고리 인기 상품 → 신상품.
- 헤더: 모바일 검색창을 별도 줄로 배치하고 카테고리 버튼을 줄여 메뉴 탐색 공간을 확보했다.
- 상품 카드·갤러리: `object-contain`으로 사진을 자르지 않고, 실패한 외부 사진은 실제 존재하는 SVG 대체 이미지로 표시한다. 첫 대표 사진과 상세 주 이미지만 우선 로드하고 목록은 지연 로드한다.
- 목록: 모바일 정렬 선택 메뉴, 하위 카테고리 탐색, 검색 결과 제목. 필터·정렬은 기존 URL 및 API 흐름을 유지한다.
- 상세: 상품 위치 링크, 갤러리·상품 정보 비율, 가격 면, 찜 아이콘, 콘텐츠 카드. 응답에 없는 리뷰 수를 0개로 단정하지 않는다.
- 구매·계정: 장바구니 모바일 행 배치, 주문 요약·주문서 카드, 인증 폼과 마이페이지 여백을 맞췄다. 할인율이 0인 장바구니 상품에서 문자 `0`이 표시되는 조건식도 수정했다.
- 공통: 키보드 포커스와 움직임 줄이기, 기본 메타데이터, 푸터.

판매자·관리자 콘솔 셸과 결제·인증·인가 흐름, DB 스키마는 변경하지 않았다. 백엔드 상품 응답에는 DB에 이미 있는 상세 스펙·리뷰 수·찜 수를 추가했다.

## 데이터 확인과 제약

첫 디자인 검토는 운영 공개 API의 상품 337개로 진행했다. 이후 사용자가 Docker를 연결하고 로컬 DB 활용을 요청하여 PostgreSQL `localhost:15432`에 읽기 전용으로 접속했다. 로컬 DB에는 상품 352개(published 339, sold_out 13), 이미지 1,050개, 리뷰 1,855개, 할인 상품 178개, 판매자 연결 상품 3개가 있다. 하위 카테고리까지 합친 상품 수는 의류 50, 뷰티 50, 신발 49, 책 100, 식품 52, 생활용품 50이다. 이는 운영 DB의 수치가 아니라 로컬 DB 조사 결과다.

홈에 등장하는 상품·카테고리·브랜드·가격은 기존 API 응답이다. 기간 조건이 없는 목록에 ‘이번 주’라는 문구를 붙이지 않고, 구현하지 않은 행사나 혜택도 추가하지 않았다. 새 카테고리 컬렉션은 기존 카테고리 인기 탭과 동일한 쿼리를 공유한다.

`ProductResponseDto`가 누락하던 `specs`, `reviewCount`, `wishCount`를 노출해 목록·검색·상세에서 사용할 수 있게 했다. 상품 카드에는 실제 리뷰 수를 표시하고 상세 화면의 리뷰·찜 집계도 DB 값을 받는다. 스펙 349개는 영문 필드명을 한국어로, 피부 타입·성별·계절 코드값을 읽기 쉬운 값으로 표시한다. 숫자 용량·중량·쪽수는 단위를 붙이고 문자열에 이미 있는 단위는 보존한다. 중첩 영양 정보와 배열도 텍스트로 표시하며 알려지지 않은 필드는 그대로 보존한다.

판매자 탭의 상품 탐색 링크는 `sellerId` URL → 서버 프리패치/클라이언트 쿼리 → 기존 백엔드 필터로 연결했다. 판매자 필터가 있는 쿼리는 별도 캐시 키를 쓰고 기존 일반 상품 목록 키는 유지한다. 태그·태그 연결·AI 리뷰 요약은 로컬 DB에 데이터가 없으므로 가짜 데이터를 추가하지 않았다.

## 확인 방법

```powershell
yarn nx build frontend
yarn nx lint frontend
node scripts/design/verify-refresh.mjs --base http://127.0.0.1:3100 --out tmp/refresh-design
```

`verify-refresh.mjs`는 데스크톱 1440px, 모바일 390px, 작은 모바일 320px에서 상품 탐색·검색·정렬·상세 탭·키보드 카테고리 메뉴·이미지 오류 대체·API 오류 상태·가로 넘침·런타임 오류를 검사한다. 장바구니·주문서·마이페이지는 브라우저 내부 픽스처로만 검사하며 실제 주문·계정 변경이나 결제를 수행하지 않는다.

이 세션의 로컬 프리뷰는 읽기 전용 공개 데이터 스냅샷으로 실행했다. `scripts/design/preview-fixture.mjs`는 `tmp/ui-public-catalog.json`, `tmp/ui-public-categories.json`을 필요로 하며, 이 파일들은 조사 중 조회한 공개 API 응답으로 Git에 포함되지 않는다. 픽스처 서버는 localhost에만 바인딩하고 GET 외 요청을 거절한다. 리뷰는 프리뷰용 빈 목록이므로 운영 리뷰 데이터 검증을 대신하지 않는다.

운영 빌드 프리뷰를 사용할 때는 빌드 시와 실행 시 API 타깃을 동일하게 맞춘다:

```powershell
$env:API_PROXY_TARGET='http://127.0.0.1:4310/v1'
$env:NEXT_PUBLIC_API_URL='/api'
yarn nx build frontend
node scripts/design/preview-fixture.mjs --production
```

스크린샷과 검사 결과는 `tmp/refresh-design/`에 생성한다. 전체 화면 촬영 전 페이지를 스크롤해 지연 로딩 사진을 불러온다.

## 검증 결과

- 프론트 운영 빌드와 TypeScript 검사 통과.
- 프론트 전체 ESLint 오류 0개. 기존 경고 29개는 남아 있다.
- 운영 빌드에서 1440·390·320px의 위 공개 화면·라우팅 및 계정 화면 픽스처 검사 통과.
- 카테고리 메뉴의 키보드 열기·하위 링크 포커스·Escape 복귀, 외부 이미지 실패 대체와 상품 API 실패 상태 통과.
- 가로 넘침과 브라우저 런타임 오류 없음.
- 위 초기 스냅샷 검증에는 실제 DB와 리뷰 내용 검증이 포함되지 않는다. 후속 실제 DB 검증은 아래에 기록한다. 운영 계정 로그인·주문 생성·결제는 수행하지 않았다.

## 실제 로컬 DB 연결과 후속 검증

Docker의 PostgreSQL·Redis를 실행한 상태에서 다음 순서로 실행한다. 백엔드는 루트 및 `backend/.env`의 로컬 접속 설정을 사용한다. 기존 환경 파일을 수정하지 않는다.

```powershell
yarn nx build backend
node scripts/design/preview-local.mjs --backend
# 별도 터미널: 프론트 빌드와 시작
$env:API_PROXY_TARGET='http://127.0.0.1:4000/v1'
$env:NEXT_PUBLIC_API_URL='/api'
yarn nx build frontend
node scripts/design/preview-local.mjs
# 별도 터미널: 실제 API 및 브라우저 확인
node scripts/design/verify-live-catalog.mjs
```

프론트는 `http://127.0.0.1:3100`, 백엔드는 `http://127.0.0.1:4000/v1`이다. 로컬 실행 스크립트는 시드 실행·Sentry 전송·운영 푸시·Gemini 호출을 끈다. 백엔드는 기존 주문 스케줄러를 포함하는 실제 앱이므로 읽기 전용 픽스처 서버와 다르다. 상품 상세 조회는 기존 정책대로 조회 수를 증가시킨다. 직접 SQL 데이터 수정이나 스키마 마이그레이션은 수행하지 않았다.

- 스킨푸드 상품 46: API 스펙(제조국·50ml·건성), 리뷰 수 4, 실제 리뷰 목록 4개, 평점 2.8 및 찜 수 전달 확인.
- 6개 카테고리 목록에 상품이 있으며 상세 스펙·리뷰 집계 필드가 전달되는지 확인.
- 실제 API를 사용하는 운영 빌드에서 1440·390·320px의 홈·한국어 스펙·리뷰 내용·판매자 필터·가로 넘침·런타임 오류 검사 통과. 결과/화면은 `tmp/refresh-design-live/`.
- DTO 회귀 검사를 포함한 상품 컨트롤러 테스트 11개 통과. 중첩 스펙과 0인 집계 값 보존, 판매자 비공개 필드 미노출 확인.
- 스펙 포맷 테스트 3개 통과. 프론트·백엔드 빌드 통과, 프론트 전체 lint 오류 0개(기존 경고 29개).
- 수정한 백엔드 DTO/테스트 lint 통과. 백엔드 전체 lint는 기존 `@nestjs/typeorm` 모듈 경계 판정 등을 포함한 오류 67개·경고 115개로 실패했다. 이번 변경에 전체 lint 정리는 포함하지 않는다.
- Windows의 현재 Node에서 백엔드 Jest 설정을 읽을 때 `__dirname` 오류가 발생했다. `NODE_OPTIONS=--no-experimental-strip-types`, `TS_NODE_COMPILER_OPTIONS={"module":"CommonJS"}`로 실행해 테스트를 통과시켰다.

운영에서도 새 필드를 표시하려면 백엔드 배포가 필요하다. 프론트는 이전 API의 누락 필드에 대한 폴백을 유지한다. 운영 반영 시 백엔드를 먼저 배포하고 프론트를 반영한다.

## 메인 배너 애니메이션

소개 문구를 배너 위의 짧은 제목으로 줄이고 전체 너비를 배너에 사용한다. 데스크톱은 왼쪽 약 65%의 큰 `BannerCarousel`과 오른쪽 약 35%의 보조 배너 두 장으로 구성한다. 오른쪽 두 장은 서로 다른 높이로 배치한다. 모바일은 메인 배너 아래에 보조 배너 두 장을 나란히 놓는다. `public/images/banner/`의 main 배너 3장은 자동 전환하고 sub 배너 2장은 항상 표시한다. 서로 다른 이미지 비율은 `object-contain`으로 보존하며 기존 인기 상품 목록은 아래 인기 상품 섹션에서 보여준다.

루트 패키지에 설치되어 있고 카테고리 메뉴에서도 쓰는 GSAP을 재사용한다. 새 라이브러리는 추가하지 않았다. 4.5초 간격 자동 전환은 0.8초 가로 슬라이드, hover는 0.8초에 걸친 3.5% 확대다. 보조 배너에도 hover 확대·그림자·화살표 표시를 적용했다. hover·키보드 포커스·정지 버튼·숨겨진 브라우저 탭에서는 자동 전환을 멈춘다. 움직임 줄이기 설정에서는 자동 전환과 확대를 끄고 수동 탐색을 유지한다. 이전·다음·3개 선택 버튼·재생/정지·좌우 방향키를 제공하며 비활성 배너 링크는 탭 순서에서 제외한다.

기존 HEAD의 배너 코드에 있던 자동 전환·hover·포커스 정지 동작을 참고해 현재 카드형 레이아웃에 맞췄다. 기존 백엔드와 데이터 처리 코드는 이번 배너 작업에서 변경하지 않았다.

확인: `node scripts/design/verify-banner.mjs`(Chrome 설치 필요, 프론트 운영 빌드 실행 후). 1440·390·320px에서 큰 배너와 두 보조 배너의 위치·크기, 자동 전환 및 트랙 이동, hover 확대·정지, 처음/끝 순환, 방향키, 정지/재생, 이미지 로드, 움직임 줄이기, 가로 넘침·런타임 오류를 검사한다. 결과와 화면은 `tmp/refresh-design-banner/`에 저장한다. 프론트 빌드·TypeScript·전체 lint 오류 0개(기존 경고 29개)를 확인했다.

## 배너별 기획전과 평점 추천

메인 배너 순서는 `main_banner3 → main_banner2 → main_banner1`이다. 메인·보조 배너 5개 모두 각자의 기획전으로 이동한다. 콘텐츠와 배너 연결은 `frontend/src/lib/events.ts`에서 함께 관리한다.

| 경로 | 주제 | 실제 상품 조건 |
| --- | --- | --- |
| `/events/special-finds` | 좋은 발견, 더 좋은 가격 | 할인율이 0보다 큰 상품 |
| `/events/everyday-favorites` | 별점으로 만나는 좋은 취향 | 평균 평점이 0보다 큰 상품 |
| `/events/summer-edit` | 가볍게 입는 여름의 기분 | 여름 의류 카테고리 |
| `/events/gift-edit` | 선물처럼 만나는 작은 발견 | 책·생활용품과 하위 카테고리 |
| `/events/style-edit` | 오늘의 스타일, 나답게 | 의류·신발과 하위 카테고리 |

`/events`는 5개 기획전의 전체 목록이다. 상세는 주제 소개·배너 → 상품 목록 → 가격·혜택 안내 → 다른 기획전으로 구성한다. 실제 상품 카드에서 상세로 이동하며, 평점순·가격순·최신순 정렬과 12개 단위 더 보기를 제공한다. 상품 오류에는 재시도, 해당 상품이 없으면 빈 상태를 표시한다. 알 수 없는 기획전 경로는 404다.

기획전 제목·이미지·조건은 프론트에서 관리하며 행사 관리용 DB/API나 쿠폰·기간 할인 로직을 추가하지 않았다. 배너에 적힌 50%·블랙 프라이데이 등의 템플릿 문구를 실제 공통 할인 혜택으로 적용하지 않고, 화면의 안내와 상품별 실제 판매가를 기준으로 한다. 여름 의류와 선물 기획전은 상시 테마다.

현재 수백 개 규모의 카탈로그를 기존 공개 목록 API로 100개씩 조회하고 마지막 페이지까지 합친 뒤 조건을 적용한다. 첫 페이지의 일부 상품만 전체 기획전으로 오인하지 않도록 했다. 기획전 간 카탈로그 캐시는 공유하고 60초간 유지한다. 카테고리 ID는 하드코딩하지 않고 API 트리의 slug로 찾는다.

홈 ‘지금 많이 찾는 상품’은 `rating DESC`로 변경했다. PostgreSQL 내림차순에서 평점 NULL 상품이 먼저 반환되는 현상이 있으므로 기존 `filter[rating][gt]=0` API 조건을 함께 사용한다. ‘전체 보기’의 `rated=true` 조건은 목록의 RSC 프리패치·클라이언트 API 요청·쿼리 키에도 동일하게 반영한다. 이번 변경에는 백엔드·DB 변경이 없다.

검증: 프론트 운영 빌드/TypeScript와 전체 lint 오류 0개(기존 경고 29개). `node scripts/design/verify-events.mjs`로 1440·390·320px에서 배너 순서·5개 링크, 실제 API와 동일한 홈 평점순, 전체 보기 조건 유지, 기획전별 실제 상품 범위·개수, 가격 정렬·더 보기, 목록·404, 가로 넘침·런타임 오류 없음 확인. 결과와 화면은 `tmp/refresh-design-events/`에 저장한다.

추가로 브라우저에서 상품 API 503 → 오류 표시 → 재시도 후 복구, 빈 카탈로그 → 빈 상태 표시를 확인했다. 제목·소개는 한국어 단어를 중간에서 끊지 않도록 줄바꿈을 조정했다.

## 운영 반영 전 검증

운영 공개 API `https://api.ansmoon.dev/v1`에서 카테고리 6개와 평점순 조회의 200 응답을 확인했다. 평점순 상위 8개는 5.0 네 개, 4.8 네 개이며, 현재 운영 응답에는 `specs`, `reviewCount`, `wishCount`가 없다. 따라서 새 데이터 표시까지 반영하려면 백엔드를 먼저 배포해야 한다. DB 마이그레이션은 필요하지 않다.

`API_PROXY_TARGET=https://api.ansmoon.dev/v1`, `NEXT_PUBLIC_API_URL=/api`로 캐시를 건너뛴 운영 빌드와 TypeScript 검사를 통과했고, 생성된 rewrites의 API·uploads 목적지도 확인했다. API 타깃 변경 후 Nx가 이전 로컬 빌드를 재사용하는 문제를 발견해 `frontend/project.json`의 build inputs에 API·PortOne·Sentry 환경 변수를 추가했다. Nx가 해석한 실제 build inputs에도 반영되는지 확인했다.

운영 대상 프리뷰 실행이 자동 승인 검토에서 차단돼, 조회만 허용하는 `scripts/design/preview-production-readonly.mjs`로 공개 상품·카테고리를 중계했다. 인증 정보는 전달하지 않고 허용 목록 밖 GET 및 모든 쓰기 요청은 403으로 거절한다. AI 요약 생성 요청도 허용하지 않는다. 이 프록시를 타깃으로 만든 운영 빌드에서 기획전 검사 1440·390·320px를 통과했다. 배너 5개 연결·평점순·전체 보기 필터·실제 상품 범위와 개수·정렬·더 보기·404·가로 넘침·런타임 오류를 확인했다. 결과는 `tmp/refresh-design-production-events/`에 있다.

프론트 전체 lint는 오류 0개, 기존 경고 29개다. 백엔드 전체 lint 실패는 위에 기록한 미해결 검증 항목으로 남는다. 운영 계정 로그인·주문 생성·실제 결제·AI 요약 생성 및 Vercel 배포 후 검증은 이번 조회 검사에 포함되지 않는다. 현재 카탈로그 규모에서 기획전은 약 4회의 목록 조회를 사용하므로 상품이 크게 늘면 서버 필터·페이지네이션을 도입해야 한다.

같은 프리뷰에서 배너 자동 전환·hover 확대/정지·순환·키보드·재생/정지·이미지 로드·움직임 줄이기 검사도 세 화면 크기 모두 통과했다. 공개 화면 회귀 검사 역시 홈·카테고리 키보드 메뉴·이미지 실패 대체·검색·정렬·하위 카테고리·상세·인증 폼·오류 상태·가로 넘침·런타임 오류에서 통과했다. 장바구니·주문서·마이페이지는 브라우저 픽스처이며, 리뷰 탭은 프록시의 제한에 따른 실패 상태 UI 검사로 운영 리뷰 내용 검증을 대신하지 않는다. 결과는 `tmp/refresh-design-production/`와 `tmp/refresh-design-banner/`에 있다. 검증 후 프리뷰는 기존 로컬 DB API로 복원한다.
